# Лабораторна робота № 2 — NoSQL

**Дисципліна:** Сучасні технології баз даних  
**Варіант 4:** система управління лікарнею   
**Основа предметної області:** [лабораторна робота № 1](https://github.com/zlat1x/hospital-database-lab-variant-4)

## Постановка задачі

Розширено лікарняну інформаційну систему модулем структурованих лабораторних звітів. Звіт містить загальні відомості, обмежену кількість панелей та результати вимірювань із референтними межами. Досліджується доцільність документної моделі порівняно з реляційною для читання й оновлення такого агрегату.

Реалізовано два еквівалентні подання синтетичних даних:

- **PostgreSQL 16:** схема `lab2`, таблиці `report`, `panel`, `measurement`, `test_catalog`, ключі, обмеження та індекси;
- **MongoDB 7:** колекція `reports` із вкладеними панелями, JSON Schema-валідацією та індексами;
- **Redis 7:** окремий приклад моделі «ключ–значення» для відновлюваного кешу метаданих (`SET`/`GET`, hash, set, TTL).

Один документ MongoDB відповідає інформації з **чотирьох пов'язаних таблиць PostgreSQL**. Дані генеруються однією детермінованою функцією і перевіряються на еквівалентність перед вимірюваннями. Основні сутності першої лабораторної роботи не модифікуються.

Обґрунтування вибору СУБД, опис моделі, гіпотези, шість сценаріїв і обмеження експерименту — у [`docs/REPORT.md`](docs/REPORT.md).

## Результати експерименту

Порівняння продуктивності PostgreSQL і MongoDB виконано 11.11.2026 на GitHub Actions для двох наборів: 1 000 і 10 000 лабораторних звітів.

Перевірено шість сценаріїв читання та запису, відповідність даних між СУБД і базові операції Redis. Усі етапи автоматизованого запуску завершилися успішно.

- [Фактичні результати вимірювань](results/)
- [Детальний звіт та інтерпретація](docs/REPORT.md)
- [Успішний запуск GitHub Actions](https://github.com/zlat1x/hospital-nosql-lab2-variant4/actions/runs/43061424856)

Для набору 10 000 звітів PostgreSQL продемонструвала меншу затримку в усіх чотирьох сценаріях читання, MongoDB — в обох сценаріях запису. Висновки стосуються конкретної моделі та виміряного середовища.

## Середовище

Docker Desktop із Linux containers, Python 3.11+, PowerShell (Windows). Локальні порти: PostgreSQL `5436`, MongoDB `27018`, Redis `6381`. Підключення обмежені адресою `127.0.0.1`.

### Ініціалізація

```powershell
Copy-Item .env.example .env
# У файлі .env встановити локальне значення POSTGRES_PASSWORD.
docker compose up -d --wait
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Файл `.env` містить локальні параметри підключення й не включається в Git. Схема PostgreSQL створюється під час початкової ініціалізації Docker volume.

### Генерація та перевірка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m src.load --reports 10000 --patients 250
.\.venv\Scripts\python.exe -m src.validate --samples 80
```

Для повної перевірки кожного звіту передбачено `-m src.validate --all`. Завантаження замінює лише тестовий набір `lab2` / `hospital_lab2.reports`; у реальних системах для міграції необхідний окремий механізм синхронізації.

### Вимірювання швидкодії

```powershell
.\.venv\Scripts\python.exe -m src.benchmark --samples 120 --warmups 15 --write-samples 25
```

Порівнюються шість операцій: повний звіт, десять останніх ID, підрахунок відхилень, історія показника, зміна одного показника й вставка звіту. Час завантаження не входить до вимірів. Для кожної СУБД обчислюються статистики затримки (зокрема p50 і p95), зберігаються CSV/JSON та серверні плани виконання запитів.

Для дослідження залежності від обсягу можна повторити завантаження та вимірювання з параметрами `--reports 1000 --patients 50`, `--reports 10000 --patients 250` і `--reports 50000 --patients 1000`. Кожен запуск створює окремі датовані файли в `results/`.

Формування підсумкової таблиці з фактичних даних:

```powershell
.\.venv\Scripts\python.exe -m src.summarize results\benchmark_10000_YYYYMMDDTHHMMSSZ.json
```

Тут `YYYYMMDDTHHMMSSZ` замінюється часовою позначкою з імені створеного JSON-файлу. Результати залежать від обладнання та конфігурації, тому в репозиторії публікуються саме отримані вимірювання, а не наперед задані значення.

### Приклади запитів та Redis

```powershell
Get-Content db\queries.sql | docker compose exec -T postgres psql -U lab2 -d hospital_lab2 -v ON_ERROR_STOP=1
docker compose exec -T mongo mongosh --quiet /demo/queries.js
.\.venv\Scripts\python.exe -m src.redis_demo
```

Для перегляду PostgreSQL через pgAdmin: `127.0.0.1:5436`, база `hospital_lab2`, користувач `lab2`, пароль із локального `.env`. Для MongoDB Compass: `mongodb://127.0.0.1:27018/`.

Зупинити контейнери зі збереженням томів: `docker compose down`.
